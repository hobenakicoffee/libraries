# Infrastructure — Storage, Auth, Cron, Seeds

Comprehensive reference for the platform's backend infrastructure: storage buckets with RLS policies, authentication configuration, scheduled cron jobs, and seed data structure.

---

## Storage Buckets

Seven storage buckets serve different domains of the platform. All buckets are created idempotently (`ON CONFLICT (id) DO NOTHING`) in migration files.

### Bucket Overview

| Bucket | Public | Max Size | Allowed MIME Types | Purpose |
|---|---|---|---|---|
| `hobenakicoffee` | Yes | — | `*/*` | Marketing and branding assets |
| `avatars` | Yes | 2 MB | `image/jpeg`, `image/png`, `image/gif`, `image/webp`, `image/svg+xml` | User avatar images |
| `banners` | Yes | 5 MB | `image/jpeg`, `image/png`, `image/gif`, `image/webp`, `image/svg+xml` | User profile banners |
| `post-images` | Yes | 5 MB | `image/jpeg`, `image/png`, `image/gif`, `image/webp`, `image/svg+xml` | Newsletter post images |
| `shop-images` | Yes | 5 MB | `image/jpeg`, `image/png`, `image/gif`, `image/webp` | Shop product images |
| `shop-product-files` | No | 1 GB | `*/*` | Shop digital product files (private downloads) |
| `kyc-documents` | No | 10 MB | `image/jpeg`, `image/png`, `image/webp`, `image/heic` | KYC identity documents (private) |

### Storage Policies per Bucket

#### `hobenakicoffee` (public)

- **INSERT** — `service_role` only (no RLS policy for authenticated/anonymous). Managed via seed/admin scripts.
- **SELECT** — Public read (`true` for all roles). Marketing assets are publicly accessible.
- **UPDATE/DELETE** — `service_role` only.

#### `avatars` (public)

- **INSERT** — Authenticated users can upload to their own folder: `bucket_id = 'avatars' AND (storage.foldername(name))[1] = auth.uid()::text`. Admins (`is_admin()`) can upload to any folder.
- **SELECT** — Users can list their own files: `bucket_id = 'avatars' AND (storage.foldername(name))[1] = auth.uid()::text`.
- **UPDATE** — Owner only: `bucket_id = 'avatars' AND owner = auth.uid()`.
- **DELETE** — Owner only: `bucket_id = 'avatars' AND owner = auth.uid()`.

#### `banners` (public)

- Policies mirror the `avatars` bucket exactly (same 4 policies, same folder/owner patterns).

#### `post-images` (public)

- **INSERT** — Authenticated users can upload to their own folder.
- **SELECT** — Owner can list. Public bucket means CDN URLs are accessible without auth.
- **UPDATE/DELETE** — Owner only.
- **Cleanup** — Cron job `nighttime-cleanup-orphaned-post-images` removes unreferenced files nightly.

#### `shop-images` (public)

- **INSERT** — Shop owners can upload product images.
- **SELECT** — Public read (bucket is public).
- **UPDATE/DELETE** — Owner only (shop owner who uploaded).

#### `shop-product-files` (private — 1 GB limit)

- **INSERT** — Shop owners only, within their own folder.
- **SELECT** — No public read policy. Files are never accessed via direct Storage URL. All downloads go through the `download-shop-file` Edge Function which generates temporary signed URLs (60-second expiry) after verifying purchase ownership.
- **UPDATE/DELETE** — Owner only.
- **Cleanup** — Cron job `cleanup-shop-orphaned-product-files` removes unreferenced files nightly at 23:30.

#### `kyc-documents` (private — 10 MB limit)

- **INSERT** — KYC session holder only, within their own `{profile_id}/` folder. Uploaded via signed URLs generated by the `generate-kyc-upload-urls` Edge Function.
- **SELECT** — Owner can list their own documents. Managers with `kyc` access can read any.
- **UPDATE/DELETE** — `service_role` only.
- **Cleanup** — Cron job `cleanup-kyc-orphaned-files` runs hourly at 30 minutes past.

### File Path Convention

```
{bucket-id}/{user-uuid}/{filename}
```

Enforced by INSERT policies: `(storage.foldername(name))[1] = auth.uid()::text`.

## Auth Configuration

### OAuth Providers

| Provider | Enabled | Mode |
|---|---|---|
| Google | Yes | Standard OAuth 2.0 |
| GitHub | Yes | Standard OAuth 2.0 |

### Email Authentication

- **Email confirmation**: Required — `email_confirmed_at` must be non-null before sensitive operations.
- **Magic link support**: Enabled — used by the KYC mobile flow and standard passwordless login.
- **OTP**: 8-digit numeric code, 1-hour expiry window.
- **Password minimum length**: 10 characters.

### Custom Access Token Hook

`custom_access_token_hook` — a PostgreSQL function (`SECURITY DEFINER`, `SET search_path = ''`) that fires on every JWT token refresh. It queries `manager_user_roles` for the authenticating user and injects `manager_role`, `manager_permissions[]`, and `is_super_admin` into the JWT claims. Configured in `config.toml`:

```toml
[auth.hook.custom_access_token]
enabled = true
uri = "pg-functions://postgres/public/custom_access_token_hook"
```

### Captcha

**Turnstile** (Cloudflare) — used on login and signup forms to prevent automated abuse.

### Rate Limits

Configured per operation type:

| Action | Rate Limit |
|---|---|
| Sign-in attempts | Tiered per email/IP |
| Sign-up | Tiered per IP |
| Magic link requests | Cooldown enforced |
| OTP requests | Cooldown enforced |
| Edge Function calls | Per-function tier (`standard`, `strict`) |

### Email Templates

Confirmation and magic link emails are localized in **Bangla** (Bengali) with the brand name **হবে নাকি Coffee?**. Templates are managed through Supabase Auth's built-in email template editor.

### JWT Claims Structure

```json
{
  "sub": "user-uuid",
  "email": "manager@hobenakicoffee.com",
  "role": "authenticated",
  "manager_role": "super_admin",
  "manager_permissions": ["managers.create", "transactions.view", "..."],
  "is_super_admin": true,
  "exp": 1234567890
}
```

## Cron Jobs

All cron jobs use the `pg_cron` extension. Jobs are defined in schema files and run as the `postgres` role. Jobs scheduled via `cron.schedule(name, schedule, command)` are idempotent — re-running with the same name updates the job.

| Job Name | Schedule (UTC) | Purpose | Source File |
|---|---|---|---|
| `nighttime-membership-expiry-notifications` | `0 22 * * *` (22:00 daily) | Notify creators about expiring memberships | `memberships.sql` |
| `create-next-month-messages-partition` | `0 0 25 * *` (25th of each month) | Create next month's `messages` partition 5-6 days before month start | `messaging.sql` |
| `drop-old-message-partitions` | `0 2 * * *` (02:00 daily) | Drop message partitions older than 6 months | `messaging.sql` |
| `nighttime-cleanup-orphaned-post-images` | `0 2 * * *` (02:00 daily) | Delete unreferenced post images from storage | `newsletter_service.sql` |
| `auto-deactivate-ineligible-shops` | `0 22 * * *` (22:00 daily) | Deactivate shops below COD thresholds (`cod_debt` + settlement age) | `shop_service.sql` |
| `nighttime-creator-subscription-expiry` | `0 22 * * *` (22:00 daily) | Process expired creator platform subscriptions | `platform_subscriptions.sql` |
| `expire-kyc-sessions` | `0 * * * *` (hourly, top of hour) | Mark stale KYC sessions as expired | `kyc.sql` |
| `cleanup-kyc-orphaned-files` | `30 * * * *` (hourly, 30 min past) | Delete orphaned KYC document files from storage | `kyc.sql` |
| `recompute-feed-rank-scores` | `*/30 * * * *` (every 30 minutes) | Recalculate feed item ranking scores | `feed.sql` |
| `cleanup-shop-orphaned-product-files` | `30 23 * * *` (23:30 daily) | Delete unreferenced shop product files | `shop_service.sql` |
| `dispatch-email-notifications` | `*/5 * * * *` (every 5 minutes) | Send pending email notifications from the outbox queue | `email_notifications.sql` |
| `cleanup-old-email-notification-queue` | `0 21 * * *` (21:00 daily) | Purge processed email notification queue rows older than 6 months | `email_notifications.sql` |

### Cron Security

Functions intended only for cron execution (e.g., `recompute_feed_rank_scores()`, `create_next_month_partition()`) have `EXECUTE` revoked from `public`, `anon`, and `authenticated`:

```sql
REVOKE EXECUTE ON FUNCTION public.recompute_feed_rank_scores() FROM public, anon, authenticated;
```

This prevents regular users from triggering expensive maintenance operations via the API.

## Seed Data

Seed files live in `backend/supabase/seeds/`. They are TypeScript files executed by the seed runner, plus one raw SQL file for static data that must be loaded before any TypeScript seed runs.

### Seed File Structure

| # | File | What It Seeds |
|---|---|---|
| — | `seed.sql` | Static data tables: `manager_role_permissions` (28 permission rows), `platform_settings` (fee rates, COD thresholds), `subscription_plans`, `notification_types` registry |
| 1 | `1.init.ts` | Storage buckets + RLS policies, cron jobs, first `super_admin` manager account (bootstrap) |
| 2 | `2.follows.ts` | 12 test user profiles with random follow relationships between them |
| 3 | `3.messaging.ts` | Direct conversations between test profiles, plus sample messages |
| 4 | `4.gifting.ts` | Coffee gift records between test users |
| 5 | `5.newsletter.ts` | Newsletter posts with content, subscriptions, and post-subscription mappings |
| 6 | `6.my-shop.ts` | Shop products (digital + physical), categories, product variants, base orders |
| 6.1 | `6.1.my-shop-orders.ts` | Extended/detailed shop order data with order items and tracking info |
| 7 | `7.managers.ts` | Manager profiles for all manager roles (one per role: super_admin, content_manager, support_manager, finance_manager, developer_manager) |
| 8 | `8.bd-geo-data.ts` | Bangladesh geography: 8 divisions, 64 districts, ~500 upazillas, ~4,500 unions |
| 9 | `9.creator-reports.ts` | Creator report data for testing report generation and analytics |

### Seed Helpers

#### `constants.ts`

Shared constants used across seed files:

```typescript
export const TEST_EMAILS = {
  alice: 'alice@test.com',
  bob: 'bob@test.com',
  // ... 10 more test users
};

export const SOCIAL_PLATFORMS = ['facebook', 'twitter', 'instagram', 'youtube', 'tiktok', 'linkedin'] as const;

export const PAYMENT_STATUSES = ['pending', 'paid', 'failed', 'refunded'] as const;
```

#### `utils.ts`

Helper functions used by all seed files:

```typescript
export function ok<T>(data: T): { success: true; data: T }
export function err(message: string): { success: false; error: string }
export function sleep(ms: number): Promise<void>
export function pick<T>(arr: T[]): T  // Random element selection
export function pickN<T>(arr: T[], n: number): T[]  // Random N elements
```

### Seed Execution Order

Seeds must run in numeric order due to dependency chains:

1. `seed.sql` first — establishes static reference data (permissions, settings, plans)
2. TypeScript seeds `1` through `9` in sequence — each builds on data created by previous seeds

### Dependency Chain

```
seed.sql
  → 1.init.ts (buckets, cron, admin user)
    → 2.follows.ts (requires profiles from init)
      → 3.messaging.ts (requires profiles + follows)
      → 4.gifting.ts (requires profiles)
      → 5.newsletter.ts (requires profiles)
      → 6.my-shop.ts (requires profiles)
        → 6.1.my-shop-orders.ts (requires shop products + orders)
      → 7.managers.ts (requires profiles)
      → 8.bd-geo-data.ts (independent)
      → 9.creator-reports.ts (requires profiles + follows)
```
